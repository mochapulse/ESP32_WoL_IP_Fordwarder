# ESP32_WoL_IP_Fordwarder

ESP32 firmware built with **ESP-IDF v6.0.2**. Connects to Wi-Fi (WPA2-PSK), serves
an embedded web dashboard over HTTP, and exposes a JSON REST API. Credentials and
configuration are read from an embedded `.env` file — no recompile needed for
Wi-Fi or port changes.

## Hardware

- **Target**: ESP32 (xtensa)
- **Flash**: 2 MB (single factory partition, no OTA)
- **Framework**: ESP-IDF v6.0.2

## Project structure

```
├── CMakeLists.txt              # Root project registration
├── dependencies.lock           # Locked dependency versions (committed)
├── sdkconfig                   # Kconfig — generated by menuconfig
├── managed_components/         # Downloaded dependencies (gitignored)
└── main/
    ├── CMakeLists.txt           # Component: sources, EMBED_FILES, REQUIRES
    ├── idf_component.yml        # Dependency manifest (cjson)
    ├── app.c                    # Entry point — app_main()
    ├── .env.example             # Template — copy to .env
    ├── web/
    │   ├── index.html           # Dashboard UI
    │   ├── style.css            # Dark theme
    │   └── app.js               # Status polling client
    └── utils/
        ├── dotenv.h / .c        # Embedded .env parser (up to 16 keys)
        ├── wifi_connect.h / .c  # Wi-Fi STA lifecycle + health
        ├── web_util.h  / .c     # HTTP server lifecycle (init/start/health/stop)
        └── web_API.h   / .c     # REST endpoints + cJSON construction
```

## Quick start

### 1. Configure

```bash
cp main/.env.example main/.env
```

Edit `main/.env`:

```
SSID_WIFI=your-network
PASSWD_WIFI=your-password
APP_NAME=MyESP32
WEB_PORT=80
```

| Key | Required | Default | Description |
|-----|----------|---------|-------------|
| `SSID_WIFI` | yes | — | Wi-Fi network name |
| `PASSWD_WIFI` | yes | — | Wi-Fi password |
| `APP_NAME` | no | `ESP32_WoL` | Logged at boot |
| `WEB_PORT` | no | `80` | HTTP server port |

### 2. Set target (once)

```bash
idf.py set-target esp32
```

This configures the toolchain, SoC headers, and linker scripts for ESP32.
Only needed on first setup or after `fullclean`.

### 3. Build

```bash
idf.py build
```

### 4. Flash & monitor

```bash
idf.py -p /dev/ttyUSB0 flash monitor
```

Replace `/dev/ttyUSB0` with your ESP32's serial port. Press `Ctrl+]` to exit
the monitor.

| Method | URI | Response |
|--------|-----|----------|
| `GET` | `/` | Dashboard HTML |
| `GET` | `/index.html` | Dashboard HTML |
| `GET` | `/style.css` | Stylesheet |
| `GET` | `/app.js` | Client JavaScript |

All static assets are embedded in flash — no filesystem or SD card required.

## Dependencies

This project uses one external component: [cJSON](https://github.com/DaveGamble/cJSON)
(via Espressif's component registry).

### Adding a dependency

```bash
idf.py add-dependency "namespace/name^1"
```

This writes the dependency to `main/idf_component.yml` and downloads it into
`managed_components/` on the next build.

After adding or updating a dependency, re-run `idf.py build`. The component
manager resolves versions and writes `dependencies.lock`.

### dependencies.lock

`dependencies.lock` is an auto-generated manifest that pins exact dependency
versions and hashes. **Commit it to the repo.** It ensures every developer and
CI machine gets identical component versions.

The lock file is regenerated whenever:
- A dependency is added or removed via `idf.py add-dependency`
- `idf_component.yml` is manually edited
- `idf.py fullclean && idf.py build` is run

Do not edit `dependencies.lock` by hand.

### managed_components/

This directory contains the downloaded source of external components.
It is **gitignored** — each developer generates it locally with `idf.py build`.

## idf.py cheat sheet

| Command | What it does |
|---------|--------------|
| `idf.py set-target esp32` | Configure project for ESP32 chip (run once) |
| `idf.py build` | Compile everything |
| `idf.py -p PORT flash` | Flash the built binary |
| `idf.py -p PORT flash monitor` | Flash then open serial monitor |
| `idf.py monitor` | Serial monitor only (no flash) |
| `idf.py menuconfig` | Interactive Kconfig editor |
| `idf.py clean` | Delete build artifacts, keep config |
| `idf.py fullclean` | Delete **everything** including config and downloaded deps |
| `idf.py add-dependency "x"` | Add a component dependency |
| `idf.py reconfigure` | Re-run CMake without fullclean |

### Clean rebuild workflow

```bash
idf.py fullclean       # nuke build/ and managed_components/
idf.py set-target esp32
idf.py build
```

After `fullclean`, `set-target` is required again because the CMake cache is
gone. Dependencies are re-downloaded automatically on build.

## Utils library

### `dotenv`

Loads a `.env` file embedded at link time via `objcopy`.

```c
dotenv_init();
const char *val = dotenv_get("SSID_WIFI");
int port = dotenv_get_int("WEB_PORT", 80);
```

| Limit | Value |
|-------|-------|
| Max keys | 16 |
| Key length | 32 |
| Value length | 64 |

### `wifi_connect`

Wi-Fi station wrapper with event-driven state tracking.

```c
wifi_init("SSID", "password");   // Init NVS, netif, WiFi
wifi_connect();                  // Start (auto-connects on STA_START)
const char *ip = check_LAN_ip(); // Block until connected
wifi_health();                   // true if connected and has IP
wifi_retry();                    // Retry if disconnected
wifi_disconnect();               // Disconnect and stop
get_LAN_ip();                    // Non-blocking IP getter
```

### `web_util`

HTTP server lifecycle. No knowledge of endpoints or JSON.

```c
web_init(80);         // Store port
web_start();          // Start HTTPD, register endpoints via web_API_init
web_health();         // true if server running
web_stop();           // Stop server
```

### `web_API`

Endpoint registration and JSON construction. Uses cJSON internally.

```c
web_API_init(server_handle);   // registers /* wildcard + /api/status
```

To add a new endpoint, add a static `esp_err_t handler(httpd_req_t *req)` in
`web_API.c` and register it in `web_API_init()`.
